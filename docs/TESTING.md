# Проверка проекта

## Автоматические сценарии

`npm run test:core` — 13 выполненных независимых тестов логики. Всего в `tests/` предусмотрено 13 unit-тестов. В `e2e/` — 3 сценариев, каждый запускается на desktop и mobile Chromium, то есть 6 браузерных выполнений при полном запуске.

```bash
npm install
npm run check
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты используют production-сборку, query-параметры и/или localStorage согласно функциям проекта. Не запускайте второй preview на порту 4173 одновременно. HTML-отчёт после E2E можно открыть командой `npx playwright show-report`.

Проверки, зависящие от npm, подготовлены, но не выполнены в исходной среде. Их успешность нужно подтвердить локально или в GitHub Actions; см. `CHECK_REPORT.md`.

## Ручная проверка

1. Добавить курс, проверить ограничения названия и числа уроков; пустые и дробные значения должны отклоняться.
2. Изменить название, направление и прогресс. Уменьшить общее число ниже пройденного: получить ошибку.
3. Отметить следующий урок до завершения: кнопка дальше недоступна, общий прогресс обновлён.
4. Добавить курс в избранное; проверить все разделы, поиск, направление, сортировку и пустое состояние.
5. Удалить курс с подтверждением, нажать «Восстановить»: карточка возвращается без дубля.
6. Включить тёмную тему, перезагрузить: тема, курсы и прогресс сохранены.
7. Сузить окно: открыть мобильное меню, выбрать раздел, проверить диалог, клавиатурный фокус и отсутствие горизонтального прокручивания.

Дополнительно проверьте ширины 320, 390, 768 и 1440 пикселей, перемещение по элементам клавишей Tab, закрытие диалогов клавишей Escape, Console и Network в DevTools. Откройте опубликованный URL непосредственно в новой вкладке, затем перезагрузите его: ресурсы должны загружаться без 404.

## Что не заменяет E2E

Успешные unit-тесты доказывают только проверенные свойства логики. Синтаксический разбор не устанавливает библиотеки и не проверяет реальный React-rendering. Mock API в тесте подтверждает обработку заданного ответа, но не доступность живого внешнего сервиса.
